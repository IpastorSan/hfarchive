# Models in the 2026-11 selection

This guide covers the curated selection in [`examples/archive-2026-11.yaml`](../examples/archive-2026-11.yaml). It explains which hardware runs each model, what each model is good for, the benchmark scores behind it, and how far the best open models are behind the closed frontier as of 2026-11-13.

The selection has two profiles. `core` (about 876 GB) holds the models worth keeping first. `extended` adds bigger quants, second copies and niche models, for about 2.2 TB in total. Sizes below are the `approx_bytes` of the files the catalog downloads, in decimal GB.

## Hardware tiers

Every model is tagged with the tiers it is practical on. "Practical" means it runs at a usable speed, not just that it loads.

| Tag | GPU memory (VRAM) | Typical cards | System RAM assumed |
|---|---|---|---|
| `tier-8gb` | 8 GB | RTX 2070 / 2070 SUPER, 3060 Ti, 4060 | ~128 GB |
| `tier-16gb` | 16 GB | RTX 4060 Ti 16 GB, 5060 Ti 16 GB, 5070 Ti, 4080 | 64 GB minimum, 128 GB to also run the big MoE models |
| `tier-24gb` | 24 GB | RTX 3090, 4090 | 128 GB |

The RTX 5090 has 32 GB. It runs everything tagged `tier-24gb`, plus the few entries whose notes ask for a 32 GB card (FLUX.2 dev at Q8_0 with its bf16 text encoder).

The 8 GB tier assumes a lot of system RAM on purpose. With 128 GB of RAM, an 8 GB card can still run 100B+ models, as explained below.

### VRAM and RAM

VRAM is the memory on the graphics card. RAM is the computer's main memory. Both can hold model weights, but the GPU reads its own VRAM several times faster than the CPU reads RAM.

Generating text is limited mostly by memory speed: for every token, the model reads all the weights it uses for that token. A model that fits entirely in VRAM is fast. A model split between VRAM and RAM runs at roughly the speed of the RAM part.

### Dense and MoE models

A **dense** model uses all of its parameters for every token. A 27B dense model reads 27B parameters per token.

A **mixture-of-experts (MoE)** model has many expert blocks and uses only a few of them for each token. It is described by two numbers: total parameters (what you must store) and **active** parameters (what is read per token). Qwen3.8-Flash-Next has 125B total and 6B active, so each token costs about as much memory traffic as a 6B dense model.

That is why big MoE models work on an 8 GB card. llama.cpp can keep the shared layers on the GPU and the experts in system RAM (`--n-cpu-moe N`, or `-ot ".ffn_.*_exps.=CPU"`). Each token then reads only the few active experts from RAM. A dense 27B model spilled into RAM gets no such help: it must read all 27B parameters from slow memory for every token, which gives 2–4 tokens per second.

### How big is a GGUF file?

GGUF is the file format llama.cpp and ComfyUI-GGUF load. The quant name says how many bits each weight keeps.

**Size in GB ≈ billions of parameters × bits per weight ÷ 8.** Rough figures:

| Quant | Bits per weight (approx.) | GB per billion parameters |
|---|---|---|
| bf16 / F16 | 16 | 2.0 |
| Q8_0 | 8.5 | 1.06 |
| Q4_K_M, UD-Q4_K_XL | 4.8–5.3 | 0.6–0.65 |
| Q3_K_XL, IQ3 | 3.5–4 | 0.45–0.5 |
| IQ1_S, IQ2 | 1.6–2.5 | 0.2–0.3 |

Gemma 4 12B at Q4_K_M is 7.3 GB including its vision projector, which matches 12 × 0.6.

For language models, you need **VRAM + RAM ≥ file size + 10–20 %** for the context (KV cache). Image and video models need roughly **the diffusion model file + 1–2 GB of VRAM**; their text encoders can sit in system RAM.

### FP8, NVFP4 and older cards

Some files use number formats that only newer GPUs compute natively:

- **bf16**: Ampere (RTX 30) and newer. The RTX 20 series lacks it.
- **FP8**: Ada (RTX 40) and Blackwell (RTX 50). The RTX 3090 lacks it.
- **NVFP4**: Blackwell (RTX 50) only.

ComfyUI upcasts fp8 files on cards without FP8, which works but uses more memory and time. On RTX 20 and 30 cards, prefer GGUF or int8 files. The catalog uses GGUF wherever one exists.

**8 GB + RAM: Qwen3.8-Flash-Next.** It is the strongest coder that runs at a usable speed with only 6B active parameters. Qwen reports 62.5 on SWE-bench Pro (Claude Code harness), 81.0 on SWE-bench Multilingual (mini-SWE-agent) and 91.9 on LiveCodeBench v6.[^qwen38fn] Artificial Analysis measures 86.1 on Terminal-Bench 2.1 and 27.1 on FrontierCode 2.0, second in the selection only to DeepSeek-V4.1-Flash-1017 (28.5), which runs at 1–3 tokens/s.[^aa] For tool use, Qwen reports 73.5 on Toolathlon Verified (self). GLM-5.3-Flash scores higher on Terminal-Bench 4.0 (32.8 vs 25.3, AA) but runs at 2–5 tokens/s from a 1-bit quant. For quicker answers, Qwen3.6-35B-A3B (3B active, 20–35 tokens/s estimated) is the fallback.

**16 GB: Qwen3.8-27B at UD-IQ4_XS.** It fits entirely in VRAM, so it is the fastest strong option on this tier. Qwen reports 61.7 on SWE-bench Pro (Claude Code harness), 73.0 on Terminal-Bench 2.1 (Terminus harness), 90.3 on LiveCodeBench v6 and 67.1 on Toolathlon Verified (self).[^qwen3827] Speed is set by the card's memory bandwidth: roughly 15–25 tokens/s on a 4060 Ti 16 GB and 30–50 on a 5070 Ti or 4080 (estimates). The 15.3 GB file leaves little VRAM for context: skip the vision projector, quantize the KV cache to q8_0 as the Unsloth Claude Code guide does,[^unsloth-cc] and expect a few tens of thousands of tokens of context rather than 262K (estimate). With 64 GB+ of RAM and work that needs long context, run Qwen3.8-Flash-Next instead.

**24 GB: Qwen3.8-27B at UD-Q4_K_XL.** Same model, a better quant, and about 5 GB left for context. Expect roughly 35–50 tokens/s on a 3090 or 4090 (estimate). For long unattended tasks, Qwen3.8-Flash-Next with more of its layers on the 24 GB card is slower but scores higher on Artificial Analysis's harder tests: 25.3 vs 5.6 on Terminal-Bench 4.0, and 27.1 vs 14.9 on FrontierCode 2.0.[^aa]

**Fast / small: Qwen3.5-9B.** It fits in 8 GB of VRAM with room for context and runs at 40+ tokens/s (estimate). Qwen reports 65.6 on LiveCodeBench v6, 66.1 on BFCL-V4 and 79.1 on τ²-bench (self).[^qwen359] Liquid AI measured it at 51.2 on SWE-bench Verified in OpenCode.[^lfm3] Use it for quick questions, small edits, commit messages and as a sub-agent. With no GPU at all, LFM3-1.7B (1.1 GB) reports 43.4 on SWE-bench Verified in OpenCode and 71.4 on BFCL V4 (self).[^lfm3]

**Autocomplete.** The selection has no fill-in-the-middle (FIM) model for inline completion. llama-server has an infill endpoint and presets for Qwen2.5-Coder 1.5B, 3B and 7B, which download the weights when first used,[^llamaserver] and Continue recommends Qwen2.5-Coder 1.5B or 7B for autocomplete.[^continue-ac] To complete code offline, add one of these to your archive.

### Connecting a coding agent

llama.cpp's `llama-server` exposes two APIs on one port: an OpenAI-compatible one (`/v1/chat/completions`) and an Anthropic-compatible one (`/v1/messages`). Tool calling needs the `--jinja` flag, which is on by default.[^llamaserver] So any agent that can use a custom OpenAI or Anthropic endpoint can use these models.

| Agent | How to point it at `llama-server` | Documented by |
|---|---|---|
| Claude Code | `ANTHROPIC_BASE_URL=http://127.0.0.1:8080 claude` | llama.cpp announcement[^llamacpp-anthropic]; Unsloth guide[^unsloth-cc] |
| OpenAI Codex | See the Unsloth guide | Unsloth guide linked from the Qwen3-Coder-Next docs[^unsloth-coder] |
| OpenCode | Custom OpenAI-compatible provider with the server's `/v1` base URL | Unsloth OpenCode guide, shown with Unsloth's own OpenAI-compatible server[^unsloth-oc] |
| Aider | `OPENAI_API_BASE=http://127.0.0.1:8080/v1`, then `aider --model openai/<name>` | Aider docs[^aider] |
| Continue | Provider `llama.cpp`, `apiBase: http://localhost:8080` | Continue docs[^continue] |
| Cline | "OpenAI Compatible" provider: base URL, API key, model ID | Cline docs[^cline] |

Unsloth's Claude Code guide adds two settings that matter for speed. Set `CLAUDE_CODE_ATTRIBUTION_HEADER=0`, because otherwise the prompt prefix changes on every request and the server cannot reuse its cache. Use a q8_0 KV cache to save VRAM.[^unsloth-cc]

What the model cards say about agents:

- **Qwen3-Coder-Next** lists Claude Code, Qwen Code, Qoder, Kilo, Trae and Cline as supported platforms. It runs in non-thinking mode only. Unsloth notes that llama.cpp fixed its tool-call parsing in February 2026, so use a recent build.[^coder][^unsloth-coder]
- **Qwen3.8** models report their SWE-bench Pro, DeepSWE and NL2Repo scores with the Claude Code harness.[^qwen38fn][^qwen3827]
- **GLM-5.3 and GLM-5.3-Flash** report Terminal-Bench 2.1 inside Claude Code 2.1.207.[^glm53][^glm53f]
- **LFM2.5-24B-A2B** was trained inside OpenClaw, Hermes Agent, Pi and OpenCode, and **LFM3-1.7B** inside Hermes Agent, Pi and OpenClaw.[^lfm25][^lfm3]
- **gpt-oss-120b** uses the Harmony format, which llama.cpp parses natively for tool calls.[^llamafc]
- **DeepSeek-V4.1-Flash-1017** reports Terminal-Bench 4.0 with the Claude Code harness, but its card says the release ships no Jinja chat template. Check the GGUF's template before relying on tool calls.[^ds]

## How to read the tables

- Each benchmark number comes from the model's own card unless marked **(AA)**, which means it was measured by Artificial Analysis[^aa] on that model at full precision. **(self)** marks numbers from a model's own authors that have not been reproduced elsewhere and that come from smaller groups or custom benchmarks. Benchmarks from the large labs' cards are also the authors' own; treat every vendor number as self-reported until someone reproduces it.
- "—" means no published number was found. No number has been estimated.
- Every number is for the full-precision model, not for the quant in the archive. See [Caveats](#caveats).
- All sources were read on 2026-11-13 unless a leaderboard date is given.

**How far each tier is from the frontier for real coding work.**

- **Short, well-defined tasks.** On these the gap is small. Terminal-Bench 2.1 has 89 curated shell tasks, and the best local models score 84–86 against GPT-6 Astra's 88.4.
- **Long tasks and maintainer-quality changes.** Here the gap is large, and it grows as the hardware shrinks:
  - **8 GB + 128 GB RAM.** Qwen3.8-Flash-Next and GLM-5.3-Flash reach 25–33 on Terminal-Bench 4.0 against 59–65, and 18–27 on FrontierCode 2.0 against 41–49. That is roughly half the frontier.
  - **16 and 24 GB, model in VRAM.** Qwen3.8-27B is fast but reaches only 5.6 on Terminal-Bench 4.0 and 14.9 on FrontierCode 2.0, about a tenth and a third of the frontier.
  - **Small models.** They score near zero on both.

In practice, a local model on any tier is good for writing and explaining functions, tests and scripts, fixing bugs with a clear reproduction, refactoring code you are watching, and short agent loops you review step by step. It is not yet good for handing over a multi-hour task in an unfamiliar repository and expecting a mergeable result; that is where the closed models still lead by a factor of about two.

The archived quants score lower than these full-precision numbers, which widens every gap above. See [Caveats](#caveats).

### Where open models are close

- **Science knowledge.** On GPQA Diamond, Qwen3.8-Flash-Next (92.3), GLM-5.3 (91.7) and even Qwen3.8-27B (90.5) are within 4–6 points of GPT-6 Astra (96.1).
- **Older agentic coding tests.** On Terminal-Bench 2.1, Qwen3.8-Flash-Next scores 86.1 against GPT-6 Astra's 88.4. That benchmark is close to saturated, so the small gap says less than it seems.
- **Vendor-reported HLE with tools.** GLM-5.3's own 62.5 is above Anthropic's figure for GPT-6 Astra and about 5 points below Opus 5.5, but it is not runnable on these tiers.

### Where they lag, and by how much

- **Overall.** On the AA Intelligence Index, the best models in this selection score 28–33, about half of the frontier's 57–65. The best open model overall, Kimi K3.1 Pro, is 10–18 points behind the frontier.
- **Hard reasoning.** On HLE, the open models that run here score 34–43, against 55–74 for the closed flagships: 11 to 40 points behind.
- **Long agentic work.** On Terminal-Bench 4.0, the runnable open models score 25–42 against 59–65. Models that fit entirely in 16–24 GB of VRAM score close to zero.
- **Small models.** The models that run fast on an 8 GB card (Gemma 4 12B, Qwen3.5-9B) are useful assistants but score around 15 on HLE and are far behind on every agentic benchmark.
- **Image and video.** The best open image models in this selection are 150–230 Arena points behind the top closed model. The archived video models rank in the bottom fifth of both video arenas.

## Caveats

- **Quantization costs quality.** Published scores are for full-precision weights. The archived files are 1- to 8-bit quants and score lower. Measured examples from the model authors:
  - OpenJev at Q4_K_M: 82.8 % vs 83.2 % for the 16-bit model on 1,789 held-out questions (self).[^openjev]
  - Edge0's 4-bit Qwen3.6-35B-A3B: 79.8 vs 81.8 on GPQA Diamond and 86.6 vs 92.7 on AIME 2026 (self).[^edge0]
  - Qwen3-Coder-Next on Aider Polyglot: third-party runs collected by Unsloth found its UD-IQ3_XXS quant "comes close to BF16", with scores improving steadily from 1-bit to 6-bit; per-quant numbers are only in Unsloth's charts.[^unsloth-coder]
  - LTX-2.5 distilled: LPIPS 0.320 against bf16 for UD-Q4_K_XL and 0.242 for Q8_0, where 0 is identical.[^ltx]
- **Very low-bit quants lose much more.** No published scores exist for the IQ1_S and IQ2 files kept here (GLM-5.3-Flash, GLM-5.3, DeepSeek-V4.1-Flash-1017). Expect a clear drop from the table, and a large one on reasoning and coding. Treat these files as a way to run a big model at all, not at its benchmark level.
- **Self-reported numbers.** Most numbers in the category tables come from the model authors. Labs choose their benchmarks, harnesses and settings, and the same model often scores differently elsewhere. Qwen3.8-Flash-Next, for example, reports 91.7 on GPQA Diamond; NVIDIA's card lists it at 92.7 and AA measures 92.3.
- **Benchmark versions differ.** Terminal-Bench 2.0, 2.1 and 4.0 are different tests, as are HLE with and without tools, and SWE-bench under different harnesses. Compare numbers only within one column and one source.
- **Arena ratings move.** Arena and AA ratings change as votes come in; "preliminary" ratings have few votes. Values are as read on the dates given.
- **Licences.** Several models are non-commercial (FLUX.2 dev and klein 9B, OpenJev) or regionally restricted (MiniMax-H3-Image). Read each licence before using a model.
